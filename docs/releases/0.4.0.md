changes, and patches for compatible fixes. This choice does not promise that
different `0.x` binaries are interchangeable. The new features justify the minor
bump, and the workflow changes and downgrade limits are called out below.

## Release notes

### Features

- **Tabs and split panes:** open pages, templates, and library views in tabs;
  reorder them, split the workspace, move tabs between panes, and drag a sidebar
  page into a pane. Restore the primary workspace's tabs and layout per vault,
  retaining editor state and independent scrolling. Command/Ctrl+T opens Home,
  Command/Ctrl+W closes a tab, Ctrl+Tab switches tabs, and F6 switches panes.
  [#34](https://github.com/alextac98/hyperion/pull/34),
  [#35](https://github.com/alextac98/hyperion/pull/35).
- **Native page windows:** drag a page or template tab outside the window, or
  choose Move to new window. Move it back to the primary or another page window
  through a tab strip, or use Move to main window. Edits and titles synchronize
  across windows. Each page window stays with its original vault; closing the
  primary saves and closes its page windows.
  [#51](https://github.com/alextac98/hyperion/pull/51).
- **Meeting blocks:** insert `/meeting` for rich notes, a date and title, microphone
  recording or audio import, playback/download, and pasted or imported transcripts.
  Recordings persist in chunks and survive page navigation; interrupted recordings
  expose their saved audio. Configure the microphone and default meeting tab in
  Settings → Blocks. Automatic transcription and AI summaries are unavailable.
  [#37](https://github.com/alextac98/hyperion/pull/37).
- **Editable columns and block actions:** insert `/columns` for two to four columns
  containing ordinary rich blocks. Reorder columns with the grip, action menu, or
  Alt+Left/Right. Remove a column while keeping its content, or unwrap the layout
  in reading order. The block grip offers Move up/down and Delete block, with
  keyboard navigation and undo/redo. Narrow layouts stack columns.
  [#46](https://github.com/alextac98/hyperion/pull/46),
  [#50](https://github.com/alextac98/hyperion/pull/50).
- **Page context and toolbars:** each tab has its own toolbar; tags sit under the
  title. Open Outline, Connections, Version history, or Page properties from the
  page menu, and pin context across page changes. The mini outline follows the
  current heading and supports hover or keyboard navigation. Native controls and
  sidebar controls share the themed header.
  [#40](https://github.com/alextac98/hyperion/pull/40),
  [#54](https://github.com/alextac98/hyperion/pull/54).
- **Feedback shortcuts:** open a GitHub report from setup, the sidebar, or the
  page context menu. The report includes app version, OS, and architecture;
  submitting a public issue requires a GitHub account.
  [#52](https://github.com/alextac98/hyperion/pull/52).

### Fixes

- Route copy, cut, and paste to the focused editor or native field, preserving
  clipboard behavior across retained tabs and read-only history.
  [#47](https://github.com/alextac98/hyperion/pull/47).
- Keep the block grip stationary on hover and dismiss its action menu on dragging.
  Preserve nested content, formatting, assets, and undo boundaries when moving or
  unwrapping blocks. [#46](https://github.com/alextac98/hyperion/pull/46),
  [#50](https://github.com/alextac98/hyperion/pull/50).
- Select a restored page or copy after reload while preserving other tabs and pane
  layouts. Keep rename aliases and vault menus synchronized across windows, and
  retain the source tab when transfer or destination startup fails.
  [#50](https://github.com/alextac98/hyperion/pull/50),
  [#51](https://github.com/alextac98/hyperion/pull/51).
- Align the page icon with responsive titles, stabilize fractional-size workspace
  layout at non-default zoom, and defer BlockSuite virtual padding updates to avoid
  resize loops. [#33](https://github.com/alextac98/hyperion/pull/33),
  [#51](https://github.com/alextac98/hyperion/pull/51),
  [#54](https://github.com/alextac98/hyperion/pull/54).

### Compatibility and upgrade changes

- The always-open details sidebar and its Settings toggle have been replaced by
  optional page context. Use the page menu and Pin page context to retain a drawer.
  Existing `showDetails` preference data remains in exports for compatibility.
- The sidebar New page button and separate template picker have been removed.
  Use **+ beside Notes**, **Command/Ctrl+N**, or a page's child-page action to create
  a page. Use the Templates view to create from a chosen template; default page and
  journal templates remain configurable in Settings.
- Page-window sessions survive window reload; a full app restart restores the
  primary session and does not recreate detached windows.
- Permanent deletion, moving vault storage, and replacing a page in place require
  closing other windows showing that vault. Failed saves keep windows open.
- No SQLite schema upgrade is introduced relative to 0.3.0: database version stays
  **4**, document version **1**, and portable bundle version **9**. Older supported
  databases still follow the existing migrations. There is no new content removal
  in this release. Legacy prototype meeting notes are converted to ordinary rich
  note children, preserving their literal text and existing children; regression
  cases verify idempotence and leave invalid/future blocks intact.

### Internal and development changes

Development profiles and data now live in each worktree's `.hyperion-dev/`, and a
development-only blueprint identifies the UI. Previous global development folders
remain in place and are not automatically adopted. `pnpm dev:reset` removes the
current worktree's development state after its instances stop. Browser development
supports configured exact origins and optimizes the clipboard compressor.
The lockfile adds Dockview and a BlockSuite virtual-padding patch; existing Electron,
BlockSuite, SQLite schema, installer naming, and publication workflows are retained.
PR CI now includes the full desktop integration and native window suites with
failure screenshots. [#38](https://github.com/alextac98/hyperion/pull/38),
[#43](https://github.com/alextac98/hyperion/pull/43),
[#47](https://github.com/alextac98/hyperion/pull/47),
[#50](https://github.com/alextac98/hyperion/pull/50),
[#54](https://github.com/alextac98/hyperion/pull/54).

## Risks, recovery and remaining checks

The main affected paths are [window lifecycle and vault scoping](../../electron/main.ts),
[multi-window document updates](../../app/platform/sqlite-editor-storage.ts),
[save/import barriers](../../app/lib/data-operations.ts),
[meeting recording](../../app/lib/meeting-recording.ts),
[column transforms](../../app/editor/blocks/columns.ts), and the
[macOS microphone packaging metadata](../../electron-builder.yml).
The tests above cover ordinary and injected failure paths, and do not establish
that every failure is impossible.

- No unresolved application test failure was found. The expected error messages
  in native tests come from deliberate failed saves, unavailable folders/browser
  handoffs, and rejected IPC/operations.
- Linux x64 packaging and its extracted executable were exercised locally.
  macOS arm64, Windows x64 and Linux arm64 builds/launches were not available on
  this machine. macOS microphone permission prompts, physical microphone devices,
  signing/notarization and OS compositor behavior remain platform checks.
- The update preview verifies simulated UI/state only. Real downloads, signatures,
  differential updates, binary replacement and restart into the final 0.4.0 build
  remain untested. Extracted AppImage execution also does not exercise FUSE mounting
  or desktop installer integration.
- Power loss, full-disk storage failures, and all possible block types were not
  simulated. New meeting/column content has preservation coverage, but this report
  does not certify every concurrent edit/import/recording combination.

Before upgrading, create a backup from Settings → Data and keep a complete vault
export where practical. Older-schema startup makes a verified pre-migration backup
before conversion, and failures roll back the transaction. An existing schema-4
vault does not receive a new migration backup solely for 0.4.0; startup's automatic
backups and explicit backups are the recovery paths. Restore a verified backup
into a separate folder through Settings → Data, preserving the current vault.
History can restore a page as a copy and recover deleted attachment bytes.

The unchanged schema number is not a downgrade guarantee: 0.3.0 lacks the new
block editors and workspace behavior. Downgrade and preservation of all new
content by older binaries were not tested. To return to pre-upgrade state, retain
the current vault and restore a verified pre-upgrade backup into a separate folder
with an appropriate older binary. Do not delete the current vault as rollback.

## Release handoff

Proposed PR title: **docs: prepare Hyperion 0.4.0 release**.
The PR body should use this report's candidate, version, release notes, validation,
risks and handoff. The reviewable diff includes the report, two guidance
corrections, refreshed screenshot and description, and release-skill update.

1. Review and merge the preparation PR through the normal repository process. Check
   both PR jobs on its final commit. Review and appropriately test any intervening
   application changes; this evidence is tied to the recorded candidate.
2. When version preparation is requested, run **Version** on `main` with **minor**
   exactly once, after checking the package is still 0.3.0. It prepares/tests/pushes
   the 0.4.0 version commit. If it is already 0.4.0, do not bump again.
3. Check the final `main` SHA, version and successful checks. When publication is
   requested, run **Release** on `main`; record its captured SHA and wait for quality,
   all four platform builds and publication. Never hand-create a release/tag.
4. Verify published installer links, checksums and update manifests, and smoke-test
   the published installers and previous-release upgrades with disposable data.
   Confirm macOS microphone permissions and real updater installation on supported
   platforms. Follow [the release guide](../developer/release.md) for failed runs.
