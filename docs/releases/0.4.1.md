# Hyperion 0.4.1 release preparation

Prepared on 2026-10-26. This patch release changes when automatic page history
is saved. The package is versioned at 0.4.1 in this PR; merging it into `main`
starts publication automatically.

## Candidate and version

- Published baseline: [v0.4.0](https://github.com/alextac98/hyperion/releases/tag/v0.4.0),
  published 2026-10-08, commit `a124c405c1a6edbae2cff28f7a6b3c341b75d84a`
  (current `origin/main`).
- Published version: `0.4.0`. Proposed version: **0.4.1** (patch). The change fixes
  a disruptive behavior and adds a compatible, optional preference. No schema
  version or stored data format changes.

## Release notes

### Fixes

- **Writing is no longer interrupted once a minute.** Automatic page history
  used to lock every editor and cover the window with a "Finishing data
  operation…" overlay every minute. That cleared the selection and interrupted
  typing. History is now saved in the background without locking editors.

### Changes

- **History follows pauses in your writing.** A page's automatic version is saved
  after two minutes without edits, so one writing session becomes one version
  instead of one per minute. Closing a page's tab, closing its vault, and quitting
  Hyperion save pending versions right away.
- **Checkpoints during long sessions.** While you keep writing without a pause, a
  version is also saved every hour by default. Change the interval or turn it off
  in **Settings → Data → Save versions during long writing sessions**. The setting
  is per vault.
- History entries still show the single time each version was saved.

### Compatibility and upgrade changes

- Vault preferences gain an optional `historyCheckpointMinutes` field: an integer
  from 1 to 1440, or `null` to disable checkpoints. Vaults and exports without it
  use the 60-minute default. Older versions of Hyperion ignore the field.
- Existing history is not rewritten. Retention (30 days for automatic versions,
  keeping each page's newest) and deduplication are unchanged.
- The daily automatic backup no longer locks editors either.

## Validation

Environment: Linux x64 (Fedora 43), Node 22.22.2, pnpm 12.4.0.

- `pnpm lint`, `pnpm check:desktop`, and `pnpm test` all pass: 47 app tests, 73
  desktop and migration tests, and 68 block, release, and browser-development tests.
- New `tests/revision-history.test.mjs` uses a deterministic clock to cover
  burst grouping, independent per-page pauses, configured, default, and disabled
  checkpoints, invalid settings, page-specific capture, settling on vault and
  library close, deleted pages, template documents, capture failures, and
  preference validation.
- New `tests/history-pause-smoke.mjs` runs in Electron and is part of `pnpm
  test:integration`. It types into a real caret with native input events across
  the pause length and checks that the overlay never appears, the caret stays put,
  and typing continues. It also checks that the burst produces exactly one
  version, that closing the page's tab saves immediately, and that Settings
  disables, re-enables, and customizes the interval.
- Electron suites run locally with `--ozone-platform=headless`. These pass:
  main smoke (history, restore, backup, save-aware close), blocks, meeting,
  vault setup, multi-window quit, columns, and the new history smoke. Two
  suites fail identically on unmodified `main` in this headless environment
  because of native pointer and external browser requirements: block-drag and
  feedback. CI runs the full suite under xvfb.

## Risks, recovery and remaining checks

- If Hyperion is force-killed, any edits from the last two minutes that haven't
  been saved as a version yet are not in history. They are still saved in the
  page itself, and the startup capture records them as a version on next launch.
- Edits from every window go through the main process, so one set of timers
  serves the main window and detached page windows.
- No packaged-installer or upgrade-from-0.4.0 test was run on this machine. The
  data format change is limited to the optional preference above.
